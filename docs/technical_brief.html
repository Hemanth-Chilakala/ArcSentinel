FPGA fabric analyses every power cycle with FFT, wavelet and int8-neural-network engines to find the faint, erratic signature of a downed live conductor. A bare-metal RISC-V hart makes the trip decision deterministically, and Linux reports it over redundant IEC 61850 networks.

1The problem

A high-impedance fault (HIF) occurs when an energised distribution conductor touches a poorly conducting surface such as dry grass, sand, asphalt, concrete or a tree branch. The resulting current is often only a few amperes to a few tens of amperes, comparable to normal load unbalance. Overcurrent relays set above that unbalance therefore never see it. Meanwhile the contact arcs, randomly and asymmetrically, at thousands of degrees. The line stays energised, so the arc can ignite vegetation, and a live wire lying on a street or field is lethal to anyone who touches it. Power lines were implicated in the 2018 Camp Fire in California [4], the deadliest in the state’s history, and in the 2023 Lahaina fire on Maui.

HIFs are hard to detect because their only reliable fingerprints are subtle. They include harmonic and interharmonic content, high-frequency energy at each arc re-ignition, half-cycle asymmetry, and above all cycle-to-cycle randomness [1, 2]. Everyday events share parts of that signature: transformer inrush, capacitor switching, welders, rectifier loads and load steps. Separating them needs rich, continuous, multi-channel signal analysis with a dependable real-time decision path, which is exactly what an FPGA SoC offers.

What is new in ArcSentinel:

  • Mixed-criticality protection on one chip. A hard-wired fabric protection path, a deterministic bare-metal decision hart and a Linux communications stack share one PolarFire SoC, isolated so that a software crash or network attack cannot block a trip. We found no HIF device that separates these layers.
  • Every stage of detection in fabric, at fixed latency. Feature extraction and int8 inference run as dedicated logic (target < 50 µs per cycle, < 1 µs jitter). The method also differs from the patented approach: interpretable physical features (harmonics, wavelet energy, asymmetry, randomness, 3rd-harmonic phase) feed a tiny MLP, instead of a band-energy image feeding a CNN.
  • Digital-twin replay self-test. The fabric can replay recorded faults in place of the ADC for bit-exact, in-field verification.
  • Standards-native and redundant. IEC 61850 GOOSE over PRP on both GbE ports, PTP-timestamped COMTRADE records.
  • Open and measured. Open golden model and benchmark; fabric-versus-CPU latency, jitter and energy measured from the same C++ source.

3Why PolarFire SoC, and why the Icicle Kit

“Couldn’t a microcontroller do this?” The arithmetic per cycle is modest. The system requirements are what demand the FPGA SoC:

  • Determinism and isolation. Protection must never miss a sample or a deadline, and must keep working when higher-level software fails. In fabric, sampling, analysis and overcurrent protection are dedicated circuits with identical latency every cycle, independent of caches, interrupts or an OS.
  • Concurrency. Lock-step capture of 8 channels, a per-cycle FFT on every channel, wavelet and randomness features, waveform recording, inference and classic protection all run simultaneously, with none of them competing for a CPU.
  • Scalability. More feeders means replicating fabric lanes, not re-validating software timing.
  • Mixed criticality on one chip. The MSS’s AMP support lets a bare-metal decision hart and a Linux communications stack coexist, isolated by PMP, and supervised by the E51 monitor.
  • Field reliability. PolarFire’s non-volatile, SEU-immune configuration, secure boot and ECC-protected memories suit unattended outdoor equipment.

We will quantify this rather than just assert it. SmartHLS sources are plain C++, so the same feature-and-inference code is compiled for the U54 cores and benchmarked against the fabric for latency, p99.9 jitter, CPU load and energy (from the on-board PAC1934).

4Architecture

See the accompanying System Block Diagram (2 pages). In summary:

  • Acquisition. A Microchip MCP3914B (8-ch, 24-bit, simultaneous-sampling ΔΣ ADC; the revision Microchip recommends for new designs) samples Va, Vb, Vc, Ia, Ib, Ic and In at 25.6 kS/s (512 samples per 50 Hz cycle). A fabric RTL sequencer owns the SPI link, so sample timing is set by a PF_CCC clock disciplined to PTP time. A replay injector can substitute waveforms from LPDDR4 for bit-exact testing.
  • Fabric analysis. Per cycle and per channel: CoreFFT 512-point spectrum (h1–h25 plus interharmonic energy), Haar DWT D1/D2 high-frequency energy, half-cycle asymmetry, cycle-to-cycle difference energy, and 3rd-harmonic angle against voltage. A window-statistics block forms 28 inputs (mean and σ over 10 cycles, every 2 cycles) for the int8 MLP 28-32-16-7. Hard-wired 50/51 and 50N/51N elements run in parallel, straight to the trip output.
  • Decision (U54 #4, bare metal). Declares an HIF after 5 consecutive HIF windows, applies inrush and switching blocking and the utility’s alarm-or-trip policy, and timestamps events. Code runs from L2 scratchpad for determinism. This hart split (Linux on U54 #1–3, bare metal on U54 #4) is exactly Microchip’s officially supported Icicle Kit AMP configuration.
  • Communications (U54 #1–3, Linux). libiec61850 GOOSE trip publisher and MMS server, PRP via the Linux HSR/PRP driver across both ports, linuxptp, COMTRADE records, web HMI, signed model and bitstream updates. It talks to hart 4 over RPMsg (OpenAMP).

5Pre-proposal feasibility study

Before applying, we built a Python golden model (feasibility/arcsentinel_model.py) that implements the exact feature set, window logic, int8 quantization and security counter planned for hardware. HIFs use the classic Emanuel two-diode arc model [1]. Its breakdown voltages are random and asymmetric, its resistances vary cycle to cycle, and it adds build-up, intermittent extinction and HF bursts at re-ignition. Arc-current amplitudes are drawn log-uniformly from 0.5 to 50 A; because the arc conducts for only part of each cycle, the measured arc current in the test set spans 0.4–40 A rms, reaching down to the sub-ampere currents typical of vegetation contact. HIFs are placed on a simulated 11 kV feeder with noise, ±0.1 Hz frequency drift and realistic unbalance, and tested against six look-alike classes. The conventional baseline is a sensitive 51N element (30 A, 10-cycle delay) with 2nd-harmonic inrush restraint, as real feeder relays use.

What this does and does not show. All data are synthetic. The study shows that the proposed features separate HIFs from the look-alike classes, that int8 quantization costs almost no accuracy, and that the model is tiny enough for fabric. It does not yet show field accuracy. Published HIF detectors typically score noticeably lower on field data than in simulation, so these figures are an upper bound. Real-data validation, starting with the public Victorian VCIT fault database [7], is our first development task. Sections 7 and 9 describe how we close that gap: randomized physics models, hardware-in-the-loop replay, public or utility field records where licensing allows, and an alarm-only mode for early deployment.

7Verification & performance evaluation plan

  • Golden-model equivalence. Every SmartHLS function has a C++ testbench checked bit-exactly against the Python fixed-point model. The testbenches run in SmartHLS software and co-simulation, and ModelSim testbenches cover the RTL (including an MCP3914B bus-functional model).
  • On-board bit-exactness. Replay-injector runs compare on-chip features and scores with the golden model, frame by frame. The same test becomes a built-in self-test.
  • Real recorded faults. The golden model, and then the hardware via the replay injector, is run on the Victorian Government’s Vegetation Conduction Ignition Test data (CC BY 4.0) [7]. This is a reference database of staged vegetation-contact fault signatures, created to support better fault detection. We report results by current band, alongside the synthetic figures.
  • Analog hardware-in-the-loop. Randomized fault libraries are played through the DAC front-end to measure dependability, security and detection time under noise, frequency drift (±0.5 Hz) and 50/60 Hz.
  • Timing. Fabric cycle-counter timestamps at each pipeline stage, and an oscilloscope on the trip output against a replay marker pin. Wireshark with hardware timestamps on both PRP LANs.
  • Fault injection (mixed criticality). We crash Linux (sysrq-trigger) during a replayed fault and show the trip still happens. We unplug LAN A during a trip and show the GOOSE still arrives on LAN B.
  • Soak test. A 72-hour run on normal and confuser replay to bound the false-alarm rate.
  • Fabric vs software. The same C++ runs on the U54 cores under Linux and bare metal. We report latency, jitter, CPU load and energy per cycle from the PAC1934.

10Impact, scalability and adoption

  • Who benefits. Distribution utilities and rural electric co-operatives in wildfire-prone regions; operators of densely populated networks where fallen live conductors cause electrocutions; microgrids, solar farms and mines.
  • Adoption path. Alarm-only pilot beside existing relays via standard CT/VT test switches, then trip mode once confidence is established. IEC 61850 GOOSE/MMS lets it drop into modern substations with no custom wiring.
  • Commercial routes. (a) A low-cost retrofit HIF module. (b) Licensable detection IP for relay and recloser OEMs. (c) A pole-top sensor variant on a smaller PolarFire SoC.
  • Scaling up and out. Replicate lanes for multi-feeder substation units. Add detectors for broken conductors, incipient cable faults and vegetation contact as new fabric functions or signed model updates.
  • Research and education. We will publish the golden model, an open HIF waveform dataset and a benchmark so others can reproduce and improve results.
